# نظام الشيباني المحاسبي — Supabase + Offline PWA

هذه حزمة تأسيسية قابلة للتطوير لنظام محاسبي عربي يعمل بواجهة PWA، مع تخزين محلي عبر IndexedDB وطابور عمليات ينتظر عودة الاتصال.

## مهم قبل التشغيل
- لم يتم الاتصال بحساب Supabase أو تنفيذ SQL على مشروعك تلقائيًا.
- أنشئ مشروع Supabase مستقلًا للنظام الجديد، أو استخدم مشروعًا منفصلًا عن متجر العملاء. هذا يمنحك عزلًا حقيقيًا للبيانات.
- افتح `supabase/schema.sql` في SQL Editor بالمشروع الجديد ونفّذه بعد مراجعة المخطط.
- انسخ `config.example.js` إلى `config.js` وأدخل رابط المشروع ومفتاح `publishable/anon` العام فقط.
- لا تضع `service_role` أو أي مفتاح سري في ملفات الواجهة.
- انشر الملفات عبر HTTPS (مثل Netlify). افتح النظام مرة واحدة مع الإنترنت حتى يتم تحميل الملفات وتسجيل Service Worker.

## الموجود في الحزمة
- واجهة عربية RTL متجاوبة.
- لوحة مؤشرات.
- إدارة أصناف أساسية عبر نافذة منبثقة (إضافة/تعديل/حذف منطقي).\n- استيراد جماعي للأصناف من CSV/TSV، وExcel XLSX عند توفر مكتبة SheetJS عبر الإنترنت، مع معاينة أولية وتخطي المكرر وقالب CSV جاهز.
- تخزين محلي للكتالوج عبر IndexedDB.
- طابور مزامنة محلي مع `client_mutation_id` لمنع تكرار العملية عند إعادة المحاولة.
- مخطط SQL أولي لوحدات المنتجات والعملاء والموردين والفواتير والمخزون والعملات والحركات المالية.
- سياسة أمنية: الجداول مفعّل عليها RLS، والوصول التشغيلي للمستخدم المسجل فقط مع صلاحيات أساسية.

## حدود النسخة
هذه نسخة تأسيسية وليست نظامًا جاهزًا للاستخدام المالي الإنتاجي. واجهات المبيعات والمشتريات والقيود المحاسبية وتقارير الأرباح، واختبارات الصلاحيات والتسوية المتزامنة تحتاج استكمالًا واختبارًا قبل إدخال بيانات حقيقية. لا تستخدم بيانات مالية حقيقية قبل مراجعة SQL وسياسات الصلاحيات واختبار النسخ الاحتياطي.

## تشغيل محلي سريع
يمكن فتح `index.html` مباشرة للتجربة المحلية، لكن Service Worker وميزات PWA تتطلب localhost أو HTTPS. لا يمكن المزامنة مع Supabase قبل ضبط `config.js` وتسجيل الدخول.


## ملفات المرحلة الثانية
- `supabase/phase2_rpc.sql`: دوال خادم مبدئية لمزامنة الصنف واعتماد فواتير البيع والشراء ذريًا مع صلاحيات دورية.
- `PHASE2_SETUP_AR.md`: خطوات الإعداد، حدود النسخة، واختبارات ما قبل الإنتاج.

## تحديث الواجهة الاحترافي
تم تحسين الواجهة بألوان أخضر زمردي وذهبي، وبطاقات مؤشرات أوضح، وجداول ونوافذ منبثقة محسّنة للهواتف. أُدرجت الأنماط داخل `index.html` أيضًا حتى لا تظهر الصفحة بلا تنسيق إذا لم يرفع الاستضافة ملف `styles.css` أو تعذّر تحميله؛ ويظل ملف `styles.css` موجودًا للسهولة في التعديل.

ملاحظة: هذا تحديث تصميم للواجهة الحالية، وليس ادعاءً بأن جميع وحدات المحاسبة أو مزامنة Supabase قد اكتملت أو اختُبرت.


## شاشة تسجيل الدخول
- تظهر شاشة تسجيل الدخول قبل لوحة الإدارة، ولا تظهر الواجهة دون جلسة دخول محفوظة أو تسجيل دخول ناجح.
- أدخل البريد الإلكتروني نفسه الذي أنشأته في Supabase Authentication → Users، مع كلمة المرور الخاصة به؛ هذا المشروع يستخدم البريد الإلكتروني كاسم المستخدم لأن Supabase Auth لا يقبل اسم مستخدم حرًا مع `signInWithPassword`.
- يجب أن يكون للمستخدم سجل في `public.app_profiles` بدور `owner`.
- يلزم الإنترنت لأول تسجيل دخول. بعد ذلك يمكن استخدام الواجهة محليًا عند انقطاع الاتصال إذا كانت جلسة الدخول محفوظة على الجهاز.
- انشر جميع الملفات معًا على استضافة HTTPS (مثل Netlify)، بما فيها `index.html` و`app.js` و`config.js` و`sw.js`. لا تفتح `index.html` مباشرة من مدير الملفات بعنوان `content://`؛ ذلك قد يمنع تحميل بعض السكربتات والاتصال والمزامنة.
- ملاحظة: تسجيل الدخول أُضيف للواجهة، لكن مزامنة طابور التعديلات من الواجهة إلى Supabase لم تُستكمل بعد؛ لا تستخدم النسخة كدفتر حسابات إنتاجي حتى اكتمالها واختبارها.


## شاشة رمز الدخول
- تم تعديل الواجهة لتطلب رمزًا رقميًا من 6 أرقام بدل عرض البريد الإلكتروني.
- المصادقة ما زالت تتم عبر Supabase Auth لحساب المدير المرتبط بالبريد الموجود في `index.html`.
- لكي يعمل الرمز، يجب أن تكون كلمة مرور حساب المدير في Supabase هي الرمز الذي ستدخله. لا تضع الرمز داخل ملفات JavaScript.
- **تنبيه أمني:** رمز من 6 أرقام أضعف من كلمة مرور طويلة. استخدم هذا الخيار فقط مع حماية قوية ومعدل محاولات مناسب، والأفضل إعداد آلية PIN من جهة الخادم مع تحديد عدد المحاولات. لم يتم اختبار تسجيل الدخول على مشروع Supabase الفعلي.

## رمز مستخدم مستقل عن كلمة مرور المدير

1. افتح Supabase → SQL Editor.
2. نفّذ الملف `supabase/login_code_settings.sql` مرة واحدة. عند أول إنشاء للإعدادات يكون الرمز الابتدائي `383280`.
3. انشر جميع ملفات هذه الحزمة على Vercel مع الاحتفاظ بـ `config.js` الخاص بمشروعك.
4. شاشة الدخول تطلب رمز المستخدم وكلمة مرور حساب المدير في Supabase؛ الرمز ليس كلمة المرور ولا يغيّرها.
5. بعد الدخول بصلاحية `owner` استخدم زر **الإعدادات** لتغيير رمز المستخدم. التغيير يُحفظ في Supabase ولا يحتاج إلى إعادة نشر الموقع.

ملاحظة أمنية: الرمز الإضافي من 6 أرقام ليس بديلًا عن كلمة مرور قوية. لا تضع أي مفتاح `service_role` أو `sb_secret` في ملفات الواجهة. لم يُختبر الاتصال بقاعدة البيانات الفعلية من هذه الحزمة؛ نفّذ ملف SQL ثم اختبر تسجيل الدخول وتغيير الرمز.
